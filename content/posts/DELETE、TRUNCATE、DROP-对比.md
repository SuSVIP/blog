## 一、总览
- `DELETE`：**删除表里面的数据，表结构保留**，DML语句，可以回滚。
- `TRUNCATE`：**清空整张表数据，表结构保留**，DDL语句，不可回滚，重置自增主键。
- `DROP`：**直接删除整个表（数据+表结构全部删掉）**，DDL语句，不可回滚。



## 二、详细对比表

| 特性 | DELETE | TRUNCATE | DROP |
| ---- | ---- | ---- | ---- |
| 作用对象 | 表中的**行数据** | 整张表**所有数据** | **整个表（结构+数据）** |
| SQL类型 | DML（数据操作语言） | DDL（数据定义语言） | DDL（数据定义语言） |
| 能否加where | ✅ 支持，可删除部分行 | ❌ 不支持where，一次性清空全表 | ❌ 删除整张表，无where |
| 事务回滚 | ✅ 可以事务回滚 | ❌ 不能回滚（MySQL8.0 InnoDB也无法rollback） | ❌ 不能回滚 |
| 自增主键 | 不会重置，继续递增 | ✅ 重置自增主键，从初始值重新开始 | 表直接删除，主键消失 |
| 触发器 | ✅ 会触发表触发器 | ❌ 不触发触发器 | ❌ 不触发触发器 |
| 执行速度 | 慢，逐行删除记录、记录日志 | 很快，直接释放数据页 | 最快，直接删除表文件 |
| 索引约束 | 保留索引、约束 | 保留索引、约束 | 索引、约束全部一起删除 |



## 三、语法示例

### 1. DELETE
```sql
-- 删除符合条件的部分数据
DELETE FROM student WHERE id = 1;

-- 删除表全部数据（不重置自增）
DELETE FROM student;
```

### 2. TRUNCATE

```
-- 清空整张表所有数据，保留表结构
TRUNCATE TABLE student;
```

### 3. DROP

```
-- 删除整个表，结构+数据全部移除
DROP TABLE IF EXISTS student;
```



## 四、重点注意事项

1. **DELETE**
   - 只删行，表结构、索引、约束全部保留。
   - 会写入 undo 日志，量大时性能差。
   - 自增主键不会清零，新插入数据接着上一个 id 继续。
2. **TRUNCATE**
   - 等价于删掉所有行，但表结构还在。
   - 底层不是逐行删除，直接释放数据页，速度远快于`DELETE`。
   - 外键关联的表，不能直接 truncate，需要先解除外键。
3. **DROP**
   - 一旦执行，表定义、数据、索引、触发器全部消失。
   - 如果做了定时备份，才有可能恢复，**普通事务无法回滚**。



## 五、使用场景推荐

- 需要**删除部分数据**，支持条件筛选：用 `DELETE`
- 需要**清空整张表全部数据**，不需要回滚、想重置自增主键：用 `TRUNCATE`
- **不再需要这张表**，结构和数据都不要了：用 `DROP`



## 六、常见面试一句话考点

> DELETE 是 DML，逐行删，可回滚；TRUNCATE 和 DROP 是 DDL，不可回滚。TRUNCATE 只清数据，DROP 连表结构一起删除。
